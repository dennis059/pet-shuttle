# 毛孩接送管理系統 v2.0

網站使用 GitHub Pages，登入和即時資料使用既有 Firebase `pet-shuttle` 專案。Spark 方案即可運行。

## 上線

1. 保存正式版分支 `backup/v1-before-v2`。到每台曾記帳的裝置開啟舊版，匯出 JSON 並保存在私人位置。
2. 在 Firebase Authentication 啟用電子郵件／密碼，由專案擁有人建立司機及客戶兩個帳號。部署 `firestore.rules` 前保留原始規則。這份規則適用於此專用資料庫，其他路徑預設拒絕。
3. 在 Firestore 為每位使用者建立 `petShuttleRoles/{Authentication UID}`，欄位 `role` 為字串 `driver` 或 `customer`。帳號和角色分配皆由 Firebase Console 管理。
4. 使用 HTTP 伺服器開啟候選版，分別用兩個獨立瀏覽器登入。驗證下週早晚各自切換、司機確認與拒絕、改車種後回到待確認、司機新增／編輯／刪除和客戶唯讀。測試帳號未分配角色時應無法讀取兩份集合。
5. 司機選擇舊版 JSON，核對原始備份的 3 筆、26 隻及 NT$750 後才確認。再次選擇同一份檔案應顯示新增 0 筆，略過 3 筆。若同一 ID 內容不同，整批停止。
6. Firebase 權限、雙帳號同步、匯入及報表通過後，才將候選版合併到 Pages 使用的分支。用原網址驗證手機登入和同步。

## 回退

如果需回到舊版，可先匯出雲端紀錄，再將正式網站的 `index.html` 恢復成 `backup/v1-before-v2` 的同名檔案並重新部署。舊版沿用同一個來源的 `pet-shuttle.records.v1`。v2.0 只讀取該鍵以供下載，雲端寫入與瀏覽器舊版資料分開保存。

每筆預約以日期及時段識別。畫面提供台北時間的下週選擇。Firestore 規則限制可操作的角色、狀態和資料格式，日期範圍由頁面控制。
